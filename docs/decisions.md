# Decision log
| Date | Decision | Why |
|---|---|---|
| 2026-08-30 | Only two adversarial fault classes | Keep reliability as the headline; avoid the crowded IPI arena (see topic-selection/06) |
| 2026-08-30 | Never fault `execute_action` | We want to measure wrong *decisions*, not a broken recorder |
| 2026-08-30 | Deterministic scoring; LLM judge only for containment | Reviewer trust, reproducibility |
| 2026-08-30 | `execute_action` is idempotent; the **first** call is binding and later calls return `already_recorded` | Smoke test on a local 2B model looped 23× on the same action, inflating tokens ~3×. A real bank system would not permit repeat money-moving calls. `n_actions` is retained as a metric of agent discipline. |
| 2026-08-30 | Tool docstrings gained `Args:` sections | Strands' `@tool` parses that section for parameter descriptions; without it every parameter got the generic fallback `"Parameter <name>"`. Weak tool descriptions would cause tool-use failures that we would then misattribute to topology — a validity threat, not cosmetics. |
| 2026-08-30 | Supervisor uses agents-as-tools by passing Agent instances directly in `tools=[...]` | Documented Strands pattern; the SDK converts each agent to a tool taking an `input` string. Manual `@tool` wrapping is unnecessary. |
| 2026-08-30 | Containment tracing will use OpenTelemetry in-memory span export, not hand-rolled interception | Strands emits agent/cycle/LLM/tool spans natively. `SwarmResult.node_history` and `GraphResult.execution_order` give handoff structure directly. |
| 2026-08-30 | Swarm/graph limits (`max_handoffs`, `max_iterations`, timeouts) will be set explicitly and recorded | Faults are expected to increase handoffs; silently hitting a framework default would confound "topology failed" with "framework capped it". |
| 2026-08-30 | Added diagnostic metrics: `evidence_complete`, `tool_calls`, `fault_response`, `retried_after_fault` | Outcome metrics say *that* a topology failed; these say *why*. `fault_response="proceeded"` names the mechanism behind a silent wrong action. Collected from an ordered tool-call log in the chaos layer, so cost is near zero. Added before the grid runs — retrofitting after would mean re-running everything. |
| 2026-08-30 | Hypotheses reframed relative to Kim et al. (arXiv 2512.08296); λ=0 is now an explicit replication (H0) | Kim et al. already showed centralized coordination contains errors better *with reliable tools*. Our original H1/H2 predicted a known result. Replicating it at baseline, then testing whether it survives tool failure, is both more honest and more convincing. |
| 2026-08-30 | Keep our four topology names; state the mapping to Kim et al.'s taxonomy in the paper rather than adopting it | Their Decentralized = debate-to-consensus, ours = handoff-with-single-decider; our pipeline (fixed DAG) has no counterpart in their taxonomy. Wholesale adoption would misdescribe our systems. |
| 2026-08-30 | OpenRouter as the model provider; `openrouter:` added to `modelspec.py` | The study treats `model` as a control variable across three models from different families. One key and one bill keeps that a string change in the grid config rather than three integrations. Direct provider keys remain supported. |
| 2026-08-30 | Pick the workhorse (then "cheap model #1") by bake-off, not by price | The grid measures *fault response*; a model that is unreliable at tool-calling under clean conditions adds noise that would be misread as fault sensitivity. Cheapest-that-is-reliable, not cheapest. |
| 2026-08-30 | ~~Bake-off shortlist: GLM-4.7-Flash, DeepSeek V4 Flash, Gemini 3.7 Flash; frontier = Claude Sonnet 5~~ **(shortlist stands; the "frontier = Claude Sonnet 5" rung is superseded by 2026-08-31)** | Weighted τ²-bench over BFCL: it is customer-service tool workflows with a pass^k reliability metric, structurally closest to our dispute workflow. GLM leads both benchmarks at Flash-tier price. Three distinct families so the model-control dimension is meaningful. Benchmark figures come from aggregators, not verified primary leaderboards — the bake-off is what decides. |
| 2026-08-30 | ~~Three-rung model ladder: Flash-tier full grid, DeepSeek V4 Pro reduced, frontier reduced~~ **SUPERSEDED by 2026-08-31 (confounded family with capability)** | Running the full grid on a strong model risks a floor effect — near-zero failures across all topologies gives no variance to attribute, a null result for the wrong reason. It is also deployment-unrealistic (banks run cheap models at volume) and makes H6 untestable. But the primary model must clear a clean-baseline bar (≥80% success at λ=0) or we measure incompetence, not fault response. V4 Pro at ~$18 for a reduced grid is the affordable strong rung. |
| 2026-08-31 | Model design changed from a 3-family ladder to workhorse + tier control + family control | The original ladder (Flash → DeepSeek Pro → Claude) confounded family with capability: a difference at the top rung could not be attributed. Kim et al. cross 3 families × 3 tiers to avoid exactly this; we cannot afford 9 models, so we change **one variable at a time** from the workhorse. Constrains WP 0.6: the winning workhorse must have a stronger sibling in the same family. |
| 2026-08-31 | Bake-off narrowed to `deepseek/deepseek-v4-flash-0731` vs `z-ai/glm-5.3-flash`; Gemini and Anthropic dropped | Verified against the live OpenRouter model API rather than aggregator summaries. Three findings forced the change: (a) the models in the old shortlist (GLM-4.7-Flash, Claude Sonnet 5) are no longer served on OpenRouter; (b) Gemini 3.7 Flash costs $0.75/$3.75 per M, not $0.1/$0.4 — a full grid is $181, not $21, an 8.6x under-estimate; (c) **only DeepSeek and Z.ai offer a cheap-tier model with a stronger same-family sibling on OpenRouter** — Google ships no Pro tier and Anthropic no cheap tier, so neither can host a workhorse under the §5a one-variable rule. Both survivors confirmed to support `tools`, `tool_choice` and `seed`. Total study cost now $34 (DeepSeek workhorse) or $60 (GLM workhorse). |
| 2026-08-31 | Fault decisions derived from `hash(seed, tool, nth_call)`, not a sequential RNG | `runner.py` deliberately excludes topology from the seed so all four shapes meet the same faults. A sequential RNG defeated that: it only advanced on *eligible* tool calls, so a topology making more preparatory calls met a different fault pattern under the same seed (verified: `fraud_score` got `stale` when called first, nothing when called second). That confounds topology with fault exposure — precisely the comparison the paper rests on. |
| 2026-08-31 | A fault is logged only when it actually changed the tool's output | `PARTIAL` and `SCHEMA_DRIFT` have no `APPLIES_TO` restriction, so they fired on `get_transactions`, which returns a list, while `_mutate` only handled dicts — the data came back untouched but was recorded as an injected fault. That inflates `n_faults_injected` and marks episodes "faulted" where the agent saw clean data, biasing results toward "topologies are robust". `_mutate` now returns a `_NOT_APPLIED` sentinel, and both faults were extended to bite lists properly. |
| 2026-08-31 | `fault_response` split into `proceeded` / `retried_then_proceeded`, plus `fault_after_decision` | It was computed purely as `final in MONEY_MOVING`, which is also half the definition of `silent_wrong` — so H4 ("proceeded is the mechanism behind silent wrong actions") was true by construction and could never fail. The retry split gives two possible labels for the same money-moving outcome, making H4 falsifiable. `fault_after_decision` excludes episodes where the fault landed after `execute_action`. |
| 2026-08-31 | `evidence_complete` now requires that a decision was actually made | `decision_at` fell back to `len(calls)`, so "consulted before deciding" silently became "consulted at all" and an abandoned episode could score `evidence_complete=True`. |
| 2026-08-31 | Claude Haiku and the GPT-5 Nano/Mini series are out of scope for now — documented as the WP 0.6b fallback | Verified against the live OpenRouter catalogue: there are **zero `openai/` models** and **no Haiku** — Anthropic ships only Opus 5 there. Using either means a direct provider key, its own path in `modelspec.py`, and a second bill, against the standing one-key/one-bill decision. GPT-5 Nano → Mini → 5 is acknowledged as the *cleanest* tier ladder available (three tiers, one family, and the one Kim et al. used); it becomes the plan if both OpenRouter candidates miss the ≥80% bake-off bar. |
| 2026-08-31 | Named the two competing mechanisms for quiet faults and added `provenance_retained` as the discriminating diagnostic (planned with WP 1.5) | Collaborator review argued a capable LLM would spot the reason-code contradiction and that the fault "has no topology". Resolution: the fault is local but the *detecting evidence* is not — handoff summaries can drop the reason codes while the transaction history sits in a different agent's context. This predicts the single agent could be safest against quiet faults (choke-point containment predicts the opposite), so both mechanisms are registered pre-freeze and the diagnostic that separates them is specified before any grid runs. Also refined recoverability to per-episode: at λ=0.5 a second fault can remove the cross-check evidence. |
| 2026-08-31 | Registered the "evidence dial" framing and the adversarial inversion, pre-freeze | Continued collaborator discussion produced (a) a third mechanism — the supervisor uniquely co-locates all workers' reports, predicting supervisor > pipeline on quiet faults despite equal hop counts; (b) a one-axis compression of all three mechanisms (raw evidence reaching the decider: single > supervisor > pipeline > swarm) giving a falsifiable quiet-fault ordering; (c) the inversion — POISONED_TOOL_DOC targets downstream agents, so the same central conduit that contains accidental corruption transports injections, predicting structure helps on accidental faults and hurts on adversarial ones. Consequence for analysis: silent_wrong is always reported per fault class, never pooled. |
