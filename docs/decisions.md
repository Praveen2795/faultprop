# Decision log
| Date | Decision | Why |
|---|---|---|
| 2026-08-30 | Only two adversarial fault classes | Keep reliability as the headline; avoid the crowded IPI arena (see topic-selection/06) |
| 2026-08-30 | Never fault `execute_action` | We want to measure wrong *decisions*, not a broken recorder |
| 2026-08-30 | Deterministic scoring; LLM judge only for containment | Reviewer trust, reproducibility |
| 2026-08-30 | `execute_action` is idempotent; the **first** call is binding and later calls return `already_recorded` | Smoke test on a local 2B model looped 23× on the same action, inflating tokens ~3×. A real bank system would not permit repeat money-moving calls. `n_actions` is retained as a metric of agent discipline. |
| 2026-08-30 | Tool docstrings gained `Args:` sections | Strands' `@tool` parses that section for parameter descriptions; without it every parameter got the generic fallback `"Parameter <name>"`. Weak tool descriptions would cause tool-use failures that we would then misattribute to topology — a validity threat, not cosmetics. |
| 2026-08-30 | Supervisor uses agents-as-tools by passing Agent instances directly in `tools=[...]` | Documented Strands pattern; the SDK converts each agent to a tool taking an `input` string. Manual `@tool` wrapping is unnecessary. |
| 2026-08-30 | Containment tracing will use OpenTelemetry in-memory span export, not hand-rolled interception | Strands emits agent/cycle/LLM/tool spans natively. `SwarmResult.node_history` and `GraphResult.execution_order` give handoff structure directly. |
| 2026-08-30 | Swarm/graph limits (`max_handoffs`, `max_iterations`, timeouts) will be set explicitly and recorded | Faults are expected to increase handoffs; silently hitting a framework default would confound "topology failed" with "framework capped it". |
| 2026-08-30 | Added diagnostic metrics: `evidence_complete`, `tool_calls`, `fault_response`, `retried_after_fault` | Outcome metrics say *that* a topology failed; these say *why*. `fault_response="proceeded"` names the mechanism behind a silent wrong action. Collected from an ordered tool-call log in the chaos layer, so cost is near zero. Added before the grid runs — retrofitting after would mean re-running everything. |
| 2026-08-30 | Hypotheses reframed relative to Kim et al. (arXiv 2512.08296); λ=0 is now an explicit replication (H0) | Kim et al. already showed centralized coordination contains errors better *with reliable tools*. Our original H1/H2 predicted a known result. Replicating it at baseline, then testing whether it survives tool failure, is both more honest and more convincing. |
| 2026-08-30 | Keep our four topology names; state the mapping to Kim et al.'s taxonomy in the paper rather than adopting it | Their Decentralized = debate-to-consensus, ours = handoff-with-single-decider; our pipeline (fixed DAG) has no counterpart in their taxonomy. Wholesale adoption would misdescribe our systems. |
| 2026-08-30 | OpenRouter as the model provider; `openrouter:` added to `modelspec.py` | The study treats `model` as a control variable across three models from different families. One key and one bill keeps that a string change in the grid config rather than three integrations. Direct provider keys remain supported. |
| 2026-08-30 | Pick cheap model #1 by bake-off, not by price | The grid measures *fault response*; a model that is unreliable at tool-calling under clean conditions adds noise that would be misread as fault sensitivity. Cheapest-that-is-reliable, not cheapest. |
| 2026-08-30 | Bake-off shortlist: GLM-4.7-Flash, DeepSeek V4 Flash, Gemini 3.7 Flash; frontier = Claude Sonnet 5 | Weighted τ²-bench over BFCL: it is customer-service tool workflows with a pass^k reliability metric, structurally closest to our dispute workflow. GLM leads both benchmarks at Flash-tier price. Three distinct families so the model-control dimension is meaningful. Benchmark figures come from aggregators, not verified primary leaderboards — the bake-off is what decides. |
